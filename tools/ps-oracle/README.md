# ps-oracle: photocraft-cli vs real Adobe Photoshop

Ground truth here is **Adobe Photoshop itself**, driven by ExtendScript. It is not psd-tools,
and it is not the PSD's embedded composite.
Each case opens a PSD, applies ops (hide, show, move, rasterize), and then writes outputs:
the canvas, single-layer exports (trimmed and full canvas), a group export, and slices. The
same case is run with photocraft-cli on the box, and the PNGs are diffed.

| file | side | what |
|---|---|---|
| `cases.json` | both | the manifest (generated by `gen_cases.py`) |
| `gen_cases.py` | box | picks layers per curated PSD from `photocraft-cli info` and writes `cases.json` |
| `scan_corpus.py` | box | corpus survey: writer/creator tool, slices, ICC, mode and depth, layer kinds |
| `ps_runner.jsx` | Mac | the Photoshop runner (ES3 ExtendScript) |
| `run-photoshop.sh` | Mac | the osascript wrapper; blocks until Photoshop finishes |
| `bundle.sh` | box | packs PSDs, cases.json, the jsx, run-photoshop.sh and this README into `/workspace/ps-oracle-bundle.tar.gz` |
| `run_photocraft.py` | box | runs the same cases with photocraft-cli |
| `compare.py` / `compare.sh` | box | diff and report: `summary.md`, `summary.json` and `diff/*.png` heatmaps |
| `test/check_jsx.js` | box | ES3 syntax check plus a dry run of the jsx against a mock Photoshop DOM |

## Running

On the Mac (Photoshop installed, any version; it is addressed as `com.adobe.Photoshop`):

```sh
mkdir -p ~/ps-oracle-run && tar -xzf ps-oracle-bundle.tar.gz -C ~/ps-oracle-run
cd ~/ps-oracle-run/ps-oracle && ./run-photoshop.sh            # all cases -> ./ps-out
./run-photoshop.sh . ./ps-out 'slices|render'                  # optional: a subset, by case-id regex
```

- On the first run, macOS asks to let Terminal control Adobe Photoshop (Automation). Allow it.
- `osascript` blocks until the script returns. Success is marked by `ps-out/DONE`.
- `ps-out/results.json` is rewritten after every case. If the run dies, the cases finished so
  far are still there.
- Fallback: in Photoshop use File › Scripts › Browse… → `ps_runner.jsx`, and pick the bundle folder.
  Output then goes to `<bundle>/ps-out`.

Copy `ps-out/` back to the box, then run:

```sh
tools/ps-oracle/compare.sh /path/to/ps-out [/workspace/pso-report]
```

This re-runs photocraft-cli for every case into `/workspace/pso-box` (about 10 s) and writes the report.

## Layout

Each output goes to `<out>/<case id>/<output name>.png`, the same on both sides:

- `canvas.png`
- `trimmed.png` and `full.png`
- `layer.png`, after a rasterize op
- `group.png`
- `slice_NN.png`, where NN is the PS slice number
- `sfw/*.png`, a Save for Web slice set with its names chosen by the exporter (compared by file name)

## Ops: how each side does it

| op | Photoshop (`ps_runner.jsx`) | photocraft-cli |
|---|---|---|
| hide / show | `layer.visible = …` (DOM; no selection, so nothing else changes) | `layer.setProps {visible}` |
| move above / below | `layer.move(target, PLACEBEFORE / PLACEAFTER)` | `layer.moveTo position=above/below` |
| move into | `move(PLACEBEFORE group.layers[0])`, i.e. the top of the group, like dropping on a group row | `layer.moveTo position=into` (also the top of the group) |
| rasterize | AM `rasterizeLayer` with `what` = `type`, `shape`, `placed` (smart object) or `layerStyle`, on the layer by id. If AM fails, DOM `rasterize()` is used and a warning is recorded | `layer.rasterize.<what>` |
| canvas | `doc.saveAs(PNG, asCopy)`: PS's own merge, transparency kept | `run … --out canvas.png` |
| layer trimmed | Layer › Duplicate Layer › New document (AM `make document using layer`), all layers visible, then `trim(TRANSPARENT)` and save | `layer.quickExportAsPng` |
| layer full canvas | the same as trimmed, without the trim | `quickExportAsPng trim=false` when the build has it. Otherwise `layer.duplicate document=new` and `--out` |
| group | the same as layer trimmed, on the group | `layer.quickExportAsPng` on the group |
| slices | duplicate the doc, crop to each user slice rect from `cases.json`, save PNG. Also a best-effort `exportDocument(SAVEFORWEB, PNG-24)` into `sfw/` | `file.export.saveForWebLegacy png24 convertToSrgb=false numbers=[n]`, plus an `all` set into `sfw/` |

Every case reopens the PSD fresh. The Photoshop side wraps each case in try/catch and closes every
document it opened with DONOTSAVECHANGES. It sets `displayDialogs = NO`, and rulerUnits and
typeUnits to pixels, and restores all three at the end.

Layer paths are `[{name, index}]`, top level first. `index` counts siblings from the top, which
is Photoshop's `doc.layers` order and also `photocraft-cli info` order. Both sides resolve by
index and check the name. A fallback to search by name is logged as a warning.

## Colour assumptions

- **No colour conversion on either side.** Values are the document's raw channel values.
  - Photoshop: Save As PNG does not convert. Save for Web and Quick Export are avoided for the
    main outputs because they may convert to sRGB.
  - photocraft: `convertToSrgb=false`, with no ICC embedded.
- `compare.py` **ignores ICC profiles** and compares premultiplied RGBA in 8-bit units, so the
  colour of fully transparent pixels is ignored. Gray and indexed PNGs are expanded to RGBA.
- Every corpus file is 8-bit RGB. 16/32-bit documents would be converted to 8 bits on a
  duplicate before saving.
- `layer-comps` is tagged Adobe RGB (1998) and several files are untagged. With dialogs off,
  Photoshop opens them by the colour-settings policy (default: preserve embedded, leave untagged
  alone). That keeps raw values, so the comparison is still value-for-value.
- Photoshop's own blending settings matter. Check Edit › Color Settings: "Blend RGB Colors
  Using Gamma" and "Blend Text Colors Using Gamma". `results.json` records `app.colorSettings`.
  Use Photoshop's defaults (North America General Purpose 2 or similar), where the RGB gamma
  blend is off.
- Text: fonts that are missing on the Mac are listed per case (`missingFonts`). With dialogs
  off, Photoshop does not update legacy text layers and draws their stored pixels. Rasterize
  Type can re-render with a substitute font. Treat type rows with missing fonts as unreliable.

## Corpus

There are 39 PSDs. Every one was saved by Photoshop, and `cases.json` → `files[].creatorTool`
gives the version (CS3 through 27.9). They cover:

- groups, hidden groups and layers
- type, shapes, smart objects
- layer effects and strokes
- blend modes, including pass-through, knockout and isolation
- masks and vector masks
- adjustment and fill layers
- clipping
- an artboard
- slices: `slices.psd` (2 image user slices) and `smart-object-slice.psd`

The PSDs come from `/workspace/photocraft/corpus`, which is gitignored. `bundle.sh` copies them.

To regenerate the manifest:
`python3 tools/ps-oracle/gen_cases.py --cli target/release/photocraft-cli --corpus /workspace/photocraft/corpus > tools/ps-oracle/cases.json`

## Checking the jsx without Photoshop

```sh
python3 tools/ps-oracle/run_photocraft.py --cli target/release/photocraft-cli \
  --bundle /workspace/ps-oracle-bundle/ps-oracle --out /workspace/pso-box --dump-info /workspace/pso-info
node tools/ps-oracle/test/check_jsx.js tools/ps-oracle/ps_runner.jsx \
  /workspace/ps-oracle-bundle/ps-oracle /workspace/pso-info /tmp/pso-dry   # needs acorn (npm i acorn)
```

The dry run checks the jsx's control flow, path resolution, op dispatch and result
bookkeeping. It produces no pixels.
